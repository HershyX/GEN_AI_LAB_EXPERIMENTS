# Week 1: First LLM API Call

## 1. Overview & Objective
The goal of this experiment is to establish a secure connection between a Python application and a Large Language Model (Google Gemini API) to generate text responses. This experiment demonstrates how to authenticate with an LLM provider using environment variables rather than hardcoding sensitive credentials in source code.

---

## 2. What the Experiment Does
1. **Loads Environment Variables:** Uses `python-dotenv` to read `GEMINI_API_KEY` and optional `GEMINI_MODEL` from the `.env` file into process memory.
2. **Authenticates API Client:** Initializes Google GenAI's official Python SDK client (`genai.Client`) with the authenticated key.
3. **Dispatches Prompt:** Submits a structured prompt (*"What is Artificial Intelligence? Explain in simple words."*) to the language model.
4. **Handles High-Demand Spike Fallback:** If the primary configured model experiences temporary server capacity spikes (HTTP 503), the client automatically falls back to `gemini-3.5-flash-lite` to ensure high availability.
5. **Displays Output:** Formats and prints the natural-language response generated by the model.

## 4. Setup & Configuration

### Prerequisites
* Python 3.10+ (Virtual environment in `../Myenv`)
* Google Gemini API Key from [Google AI Studio](https://aistudio.google.com/)

### Environment Configuration (`.env`)
```env
GEMINI_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-3.5-flash-lite
```

### Dependencies (`requirements.txt`)
* `google-genai`
* `python-dotenv`
* `pytest`

## 7. Key Concepts Covered
* **Secret Management:** Storing API keys in `.env` files rather than hardcoding them in Python files.
* **REST/gRPC SDK Client:** Interfacing with Google's GenAI API through structured client calls.
* **Model Availability & Fallback:** Addressing provider availability states (e.g., 503 capacity limits) through resilient client design.
